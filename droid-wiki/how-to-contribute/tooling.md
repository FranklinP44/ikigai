# Tooling

The project uses no build system, package manager, linter, or formatter. This page lists what exists and what is safe to use.

## What exists

| Tool | Status |
| --- | --- |
| Build system | None. Files are served as-is. |
| Package manager | None. There is no `package.json`. |
| Linter / formatter | None configured. Code uses two-space indentation and double quotes in JavaScript. |
| CI | A GitHub Actions workflow publishes this wiki to Confluence (see below). There is no CI for the app itself. |
| Local server | Any static server, for example `python3 -m http.server` or `npx serve .` |

## Wiki publishing

This wiki lives in `droid-wiki/` and is generated by Factory's `/wiki` command. When changes to `droid-wiki/` merge into `main`, the workflow in `.github/workflows/publish-wiki-to-confluence.yml` runs `.github/scripts/publish_confluence.py`. That script converts each page to Confluence format, renders Mermaid diagrams to images, and creates or updates the matching Confluence pages under a single root page. On pull requests it runs in dry-run mode as a check, without writing to Confluence.

## Optional tools you can run ad hoc

These are not part of the repository, but they work without adding config:

```bash
npx prettier --check index.html script.js styles.css
npx html-validate index.html
```

If any of these become part of the workflow, add their config files and a note here.
